# ai-training-planner

> 一个跑在你自己机器上的 AI 训练教练，只做两件事：**制定计划** —— 定动作，更定重量；**复盘** —— 并把复盘结论折算成权重，回流到下一轮计划里。

## 它是什么，不是什么

**是**一个跑在你自己电脑上的规划系统。它读懂你的训练历史，找出分化结构上的漏洞、反复出现的动作、被悄悄跳过的肌群，然后排出下一周该练什么、该上多重。周期结束时，它回头复盘这一轮练得怎么样。

**不是**又一个健身记录 App。日常记录和训练执行继续交给[训记](https://trains.xunjiapp.cn)，这个系统不抢那件事。

**完整闭环已经跑通**：读历史 → 排计划 → 人工审核 → 写回训记 → 每天记感受 → 周末复盘 → 周期末快照。

## 为什么会有这个东西

训练数据在训记里躺了很多年，没被用过。而自己排计划时反复遇到同一批问题：分化结构不科学、同一个动作刺激重复、某些肌群长期练不到、不知道下个阶段该怎么调。每次出门前还要再想一遍「今天练什么」。

这些恰好是模型擅长的事 —— **前提是别把 26 周原始记录直接倒进 prompt。**

## 核心设计取舍

这几条决定了整个系统的形状，比任何功能列表都更能说明它是什么。

**1. 不把原始历史喂给模型。**
历史先在本地压成「摘要层」（训练画像 + 周摘要 + 渐进超负荷计算结果），模型只读摘要。prompt 体积可控、输出稳定，也不会因为多练了两个月就突然变贵。

**2. 重量递增本地算，模型只裁例外。**
渐进超负荷是纯算术，不该交给概率模型。每个动作该加多少、加不动时怎么退，本地算死；模型只回答真正需要判断的问题，比如某个动作该不该换掉。

**3. 写回训记有两道栏杆，没有任何自动路径。**
`草稿 → 批准 → 预演（纯本地）→ 确认（需字面确认）→ 写入`。写入按天逐批、严格串行，批次之间留冷却窗口。每次写入都必须读回校验 —— 训记的成功响应不回显数据，不读回就无法区分「写成功」和「被限频静默丢弃」。进程被杀导致的中断写入标记为 `uncertain`，**绝不**标 `failed` —— 结果未知就绝不自动重写。

**4. 不做定时调度。**
曾经有过一个调度器，后来砍了。所有流程都由页面上的按钮触发。开机只做三件事（复位遗留任务、归档过期草稿、增量同步一次），而且每一件都是只读的。少一层「它半夜自己干了什么」的不确定性。

**5. 本地优先。**
SQLite 落在你自己的硬盘上，服务只绑 `127.0.0.1`。训练数据不出本机。

## 快速开始

前置：**Node.js >= 22.13**（用到了内置的 `node:sqlite`，不需要另外装数据库服务）。

```bash
git clone <this-repo>
cd ai-training-planner
npm install

cp .env.example .env         # Windows: Copy-Item .env.example .env
# 然后编辑 .env，至少填上 XUNJI_API_KEY

npm run build                # 编译后端
npm run build:web            # 编译前端（改动前端后必须重跑）

npm run server               # 启动，打开 http://127.0.0.1:8787
```

Windows 上也可以直接双击 `start-server.bat`（会自动探测端口是否已被占用，已启动则只打开页面）。

首次打开会有一个三步引导，带你填完训记 Key、训练基础和基础身体信息。保存 Key 后会自动拉取一次完整历史（实测 182 天约 9 秒）。

### 两个 Key

| 变量 | 必需 | 说明 |
|---|---|---|
| `XUNJI_API_KEY` | ✅ | 训记 Open API Key。不填则什么都拉不到 |
| `LLM_API_KEY` | 推荐 | 不填不报错 —— 排计划会降级成规则模板，但会失去模型贡献的那部分价值 |

两个 Key 都可以完全跳过手改 `.env`：在设置页填写，保存时会写入 `.env` 并**立即生效，不用重启**。Key 只落在 `.env`（已被 gitignore），不入库、不写日志、不回传前端，界面上只显示 `****后四位`。

AI 侧默认接 DeepSeek。任何 OpenAI 兼容端点都能用（Qwen / Kimi / 本地 vLLM / Ollama 等）—— 只改 `LLM_BASE_URL` 和 `LLM_MODEL`，协议不用动。

> ⚠️ `LLM_MAX_TOKENS` 要给大一点。它是**含推理内容的总额度**，不是「写 JSON 的额度」—— 推理模型排一份周计划会先花掉约 7700 token 思考。给 8192 会被硬切断，JSON 解析失败，然后降级到模板。默认 32768。

## 数据源：训记，以及之后

训记是目前唯一实现的接入方，但**接入层是刻意隔离的**。读侧集中在 `server/xunji/`，动作名与肌群的对应关系放在 `seeds/` 里作为通用映射表。排计划和复盘的逻辑从不直接接触训记的响应格式。

所以把它接到别的记录软件，改的是这两处，而不是排计划逻辑。把范围说清楚：这是一个**可替换的接入口**，不是即插即用的插件体系 —— 适配代码还是要自己写。

## 技术栈

| 层 | 选型 | 备注 |
|---|---|---|
| 运行时 | Node 22 + TypeScript（ESM） | 直接用 `tsc` 编译，没有打包器 |
| 数据库 | `node:sqlite` | Node 内置，零额外依赖，无 ORM |
| 后端 | 手写 `node:http` 路由 | 十几个 handler 的规模，不值得引框架 |
| 前端 | React 19 + TanStack Query 5 | hash 路由手写，没引路由库 |
| 样式 | Tailwind 4 + Vite 8 | |

## 已知边界

- **只绑 `127.0.0.1`，且没有鉴权。** 这是刻意的 —— 它是单机自用工具。**不要暴露到公网**：设置页的 Key 写入接口会改写服务器上的 `.env`，公开意味着任何人都能换掉你的 Key。想在手机上用，建议走 Tailscale 之类的私有网络，而不是端口转发。
- **不要开 GitHub Pages。** 这个项目需要 Node 后端（SQLite、同步引擎、模型调用）。仓库根目录的 `index.html` 只是 Vite 的源模板，构建产物在 `dist/web/`，必须由后端托管。
- **写回训记有硬性限频**，每批之间约 65 秒。导入一份 4 天的计划大约需要 4 分钟。这是训记服务端的限制，绕不过去。
- 开发过程中用过的一次性探针脚本**不在本仓库中**。
